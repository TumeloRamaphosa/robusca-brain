## Canonical source

The only source of truth for the public Super Agents website is:

```text
Gitea on Mac1
localhost:3000/tumelo/superagents-site.git
└── index.html
```

Vercel deploys that repository to `superagents.studex-group.com`.

The public GitHub `superagents-site` repository is an older snapshot. Agents
must not edit, fork or deploy it over Gitea. Cursor Cloud cannot reach another
machine's `localhost`, so no canonical site change was attempted.

## Product understanding

Super Agents is one product with several technical layers:

- the Gitea/Vercel site is marketing;
- Elara on Base44 is customer care/onboarding;
- Nest VM is the new private-machine delivery model;
- a control plane and client VM runtime still need to be built;
- the War Room is internal operations;
- `agentic-lab-v3` is the developer factory and should remain separate.

## Repository findings

### `studex-agents-nest`

Static HTML prototype only. Agent replies, VM actions, outreach, Discord setup,
prices and live updates are canned browser behavior. No VM provider, backend,
model, persistence, messaging or agent runtime exists.

**Disposition:** archive; reuse reviewed visuals only.

### `agentic-lab-v3`

Internal Node CLI scaffold. It performs diagnostics, filesystem/project
scaffolding, Docker commands and limited GitHub/external-CLI wrappers. It does
not provision VMs or orchestrate agents, and it is not the source of the live
Factory site.

**Disposition:** keep as an internal Developer Factory.

### `studex-agent-ecosystem`

The supplied GitHub URL returns 404 publicly and through the authenticated CLI.
The closest public repository is `agents-studex`, but that equivalence has not
been confirmed.

### `agents-studex`

Static Next.js marketing prototype with no auth, API, database, billing, VM
provisioner or agent runtime.

Public `main` contains `scripts/capture-creds.js`. It automates third-party
logins with environment-stored passwords, scrapes authenticated Notion API
tokens and writes captured material into a hidden credential directory.

A local removal commit was prepared, but GitHub rejected the push because the
Cursor bot has no write permission. The dangerous file therefore remains
public.

**Required owner action:** remove the script and its direct Playwright
dependency immediately. Rotate affected credentials if the script was ever
executed.

## Recommended MVP

Do not fork Buzz and OpenMausBot simultaneously.

Both are Apache-2.0. OpenMausBot is the closer first-runtime candidate because
it already supplies an agent harness, chat, computer use, approvals and
cloud/local desktops. Buzz is better reserved for the later shared
human/agent collaboration layer.

The first credible release should prove:

1. one authenticated tenant;
2. one provider;
3. one isolated Ubuntu VM;
4. one Super Agent runtime;
5. one private browser/computer service;
6. registration and heartbeats;
7. persistent workspace across restart;
8. audited rebuild and destroy.

WhatsApp, self-service billing, multiple providers, shared Buzz workspaces and
autonomous outbound campaigns should follow only after that lifecycle is
reliable.
